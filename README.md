# 如何教沙雕 GPT 做设计（Agent UI Design）

面向 AI Agent 与独立开发者的工业级 UI 设计工作流与 Prompt 系统。

将模糊的功能诉求，分阶段转化为状态机决策树、ASCII 原型线框图、黑白灰骨架，并最终组装为工业级标准的前端页面。

---

## 为什么大模型写出的页面总是奇丑无比？

大模型做页面丑，根源通常不在配色，而在于**信息层级失控**：
1. **防御性堆砌**：害怕遗漏信息，把所有说明、协议和次要操作逐行平铺在页面上；
2. **缺乏视觉重点**：所有文本字号相似、按钮争抢眼球，违反认知心理学上的米勒定律（人脑无法同时轻松处理超过 4 个信息单元）；
3. **审美与骨架混杂**：一边猜布局一边调渐变色，导致间距忽大忽小、出现大量手写魔法数字。

正确的解法是：**骨架层与创意层彻底分开，用分阶段的确定性规则约束大模型**。

---

## 三阶段工作流

```text
[ 功能诉求 ] 
     │
     ▼
【第一阶段：需求澄清与状态决策】── 产出：用户画像、核心动作、必留元素清单
     │
     ▼
【第二阶段：ASCII 文本原型】   ── 产出：米勒定律组块、3~4张卡片、二级弹窗抽离
     │
     ▼
【第三阶段：黑白灰骨架与设计】  ── 产出：16px间距阶梯无彩色骨架 ➜ 创意层细节组装
     │
     ▼
【第四阶段：自动化反馈与门禁】  ── 机制：每次人工纠偏沉淀为代码 Lint 与反例用例
```

## 快速使用

### 方式一：作为独立 Prompt 逐步投喂
在任何大模型（GPT-4o、Claude 3.5 Sonnet、Codex 等）中按顺序依次执行：
1. 粘贴 `01-requirement-tree.md`，输入你的业务功能；
2. 确认字段清单后，粘贴 `02-ascii-wireframe.md` 输出 ASCII 线框图；
3. 确认线框图无误后，粘贴 `03-ui-design-system.md` 第一阶段要求输出黑白灰骨架 HTML；
4. 骨架通过后，开放创意层权限完成最终细节与色彩组装。

### 方式二：作为 Antigravity / Agent 技能加载
直接将本仓库作为 Skill 挂载至你的 Agent 运行时：
```bash
# 在项目的 .agents/skills/ 目录下创建软链
ln -s /path/to/agent-ui-design .agents/skills/agent-ui-design
```
